# 原型设计模式

## 1. Tracer Bullet Pattern（示踪弹模式）

**用途**：验证端到端路径是否可行
**做法**：从入口到出口实现最薄的一条路径，不处理任何边界
**示例**：
- API原型：一个endpoint，返回硬编码数据
- UI原型：一个页面，一个按钮，一个结果
- 算法原型：一个输入，一个输出

## 2. Parallel Variants Pattern（并行变体模式）

**用途**：对比多个设计方案
**做法**：同一问题实现2-4个截然不同的方案，并排对比
**关键**：变体间差异要足够大，微调不算变体
**示例**：
- 3种不同的状态机设计（层次式/表驱动/事件溯源）
- 3种不同的UI布局（列表/网格/时间线）

## 3. Fake It Till You Make It Pattern

**用途**：验证接口设计，实现后面再做
**做法**：先用硬编码返回值让调用方能跑通，再逐步替换为真实实现
**示例**：
```python
# 原型阶段
def get_user(id): 
    return {"name": "Alice", "role": "admin"}  # 硬编码

# 真实实现阶段
def get_user(id):
    return db.query(User).get(id)  # 真实查询
```

## 4. Spike Pattern（技术探针）

**用途**：验证某个技术点是否可行
**做法**：聚焦单一技术风险点，忽略其他一切
**示例**：
- "WebSocket在这个网络环境下延迟是否可接受？"
- "这个ML模型在目标硬件上推理速度够不够？"
- "这个第三方库是否支持我们需要的功能？"

## 5. Wizard of Oz Pattern（绿野仙踪模式）

**用途**：模拟尚未实现的组件
**做法**：用人工/硬编码模拟复杂组件的行为
**示例**：
- AI功能原型：用预设回复代替真实模型
- 实时数据原型：用录制的历史数据回放
- 硬件交互原型：用键盘输入模拟传感器

## 6. Throwaway vs Evolutionary（丢弃式 vs 演化式）

| 特征 | 丢弃式原型 | 演化式原型 |
|------|-----------|-----------|
| 目的 | 回答问题 | 逐步变成产品 |
| 代码质量 | 最低可运行 | 可维护 |
| 测试 | 无 | 有 |
| 文档 | 无 | 有 |
| 生命周期 | 回答完即删 | 持续演进 |

**本技能聚焦丢弃式原型。** 如果原型可能演化，那就不是原型，是MVP。

## 选择决策树

```
要验证什么？
    │
    ├─ "逻辑/状态是否正确" → 逻辑原型（终端/脚本）
    │
    ├─ "界面/交互是否合理" → UI原型（HTML/组件）
    │
    ├─ "技术是否可行" → Spike（聚焦单点）
    │
    ├─ "方案A还是方案B" → 并行变体
    │
    └─ "整体流程是否通" → Tracer Bullet
```
